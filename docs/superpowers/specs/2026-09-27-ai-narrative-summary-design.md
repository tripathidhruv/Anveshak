# AI narrative summary (OpenAI) — design

Status: decided per explicit user directive ("start implementing it"), 2026-09-27.

## What this is

A plain-English narrative paragraph for a traced case, generated by an OpenAI model from
data KAIZEN has **already computed and already decided** — never a new source of truth. This
is purely a readability/presentation layer for officers and judges, matching the one honest
capability gap this project's own competitive research flagged (a rival, CryptoTraceDEVOPS,
has an LLM narrative layer; KAIZEN didn't).

## The one non-negotiable boundary

The LLM never makes a decision this project's rule-based engine hasn't already made. It does
not: decide whether a sweep occurred, decide gate-passed/UNKNOWN attribution, compute a risk
or innocence score, or decide anything that affects `AttributionCandidate`/`Hop`/`FlaggedWallet`
persistence. It only narrates already-computed, already-persisted fields into prose. This
matches CLAUDE.md's "label scarcity" thesis directly — the whole reason detection here is
rule-based is that an LLM (or any ML) has no real labelled fraud data to ground a *decision*
in, but narrating an *already-correct* structured finding into a sentence has no such
grounding problem, since every fact narrated is independently checkable against the
structured response it's built from.

## Architecture

- `app/narrative/summary.py` (new): `generate_case_narrative(case, hops, attribution_candidates,
  innocence) -> str | None`. Builds a prompt strictly from already-persisted data (no new chain
  reads — same "don't triple-compute" discipline already established for risk.py vs.
  traces.py vs. operator_fingerprint.py). Returns `None` (not a fabricated placeholder string)
  when: `settings.openai_api_key` is unset, the case has no persisted trace data yet, or the
  OpenAI call itself fails — honest failure, same pattern as every other feature this
  project has shipped (a `None`/empty result with a `reason`, never a silently-substituted
  guess).
- `app/api/v1/narrative.py` (new router): `GET /api/v1/cases/{case_id}/narrative` →
  `{caseId, narrative: str | None, available: bool, reason: str | None, disclosure: str}`.
  `disclosure` is present unconditionally, matching `SIMILARITY_DISCLAIMER`/
  `BRIDGE_LINK_DISCLAIMER`/`SYNTHETIC_DATA_DISCLOSURE`'s exact convention: *"This summary was
  written by an AI language model narrating the structured findings above into plain English.
  It makes no independent findings of its own and must never be treated as verified fact
  beyond what the structured data it was built from already states."*
- Config: `Settings.openai_api_key: str | None = None` (env var `KAIZEN_OPENAI_API_KEY`, same
  `KAIZEN_` prefix convention as `trongrid_api_key`/`etherscan_api_key`). The real key already
  lives in `backend/.env` (gitignored, confirmed) — this task's implementer never needs to see
  or handle the raw key value, only read it via `settings.openai_api_key`.
- Model choice: a real, current OpenAI model (implementer's call — pick a small/cheap
  chat-completion model suited to short structured-to-prose summarization, not a reasoning-
  heavy one; document the exact model string chosen and why).

## Testing/acceptance

- No test makes a real OpenAI API call — the OpenAI client is mocked in every test, matching
  this project's own "no live network calls in tests" convention (chain clients are always
  faked in tests too).
- A test confirming `available: False`/`narrative: None` with a real, honest `reason` when
  `openai_api_key` is unset, and a separate test for a case with no persisted trace data.
- A test confirming a successful (mocked) call produces `narrative` text and the disclosure
  field is present.
- A test confirming a simulated OpenAI API failure (e.g. a mocked exception) results in
  `available: False` with an honest reason, never a crash and never a fabricated narrative.

## Out of scope

No frontend screen for this in this pass (API + tests only, matching the "backend + demo
fixture, no new screen" precedent already set for operator-fingerprinting). No streaming. No
chat/Q&A interface. No use of the LLM anywhere in the detection/attribution/risk/innocence
pipeline itself.
