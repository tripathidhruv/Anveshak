## 2026-09-25 (backend, cont'd) · Dhruv + Claude · Task 6 landed after catching a real fan-out taint bug
**Did:** Task 6 (causal FIFO tracer + conservation invariant + chain registry) — the single most correctness-critical task in the plan, since KAIZEN's whole pitch is that competitors get exactly this logic wrong. Took 2 fix passes, both catching real bugs, not nitpicks:
1. **Critical:** the first implementation capped each sibling branch's taint independently (`min(taint, branch_amount)` per branch with no shared budget), so a wallet that fans out into multiple outgoing transfers could report *more* total downstream taint than it ever actually held — e.g. taint=150 split across three 100-unit branches would claim 100+100+100=300 traced, not ≤150. Fixed with FIFO budget allocation across timestamp-ordered siblings (100/50/0 for that exact case), independently hand-traced and verified by two separate reviewers.
2. **A flawed follow-on fix caught before it shipped:** a fix for a separate finding ("pass `since` to the chain client to scope real API calls") led the implementer to add a second network call per hop to distinguish two stop_reason states — but review caught that none of the three chain adapters actually do server-side time-window scoping (they all fetch unscoped, then filter client-side), so the second call bought nothing and cost a real ~340ms+ per dead-end wallet, and silently misclassified probe-call failures as "wallet never sent funds" — a real risk for evidence-pack output. Reverted to a single unscoped fetch deriving both the causal queue and the stop-reason distinction from one call, exactly like the original design.
**Decided:** User set a new standing rule mid-session: every generated string meant for a human reader (risk-score reasons, innocence/attribution reasoning, flagged-exchange explanations, trace hints, report content) must be plain, non-technical English a 12-year-old could follow — not just UI copy, extending CLAUDE.md rule 3 explicitly to backend-generated prose. Applies starting Task 7 (first task that writes any such string); Tasks 1-6 have no user-facing prose so nothing to retrofit.
**Next:** Task 7 (vetted VASP labels + gated sweep/deposit detectors) — `reasoning`/`limitations` fields must be written in plain English per the new rule, overriding the plan document's own example prose where it's too technical.
